5. Contract highlights
----------------------
- VCN 10.10.0.0/16, public subnet 10.10.1.0/24, dedicated internet gateway and
  route table; the VCN default tables are not mutated.
- Security list: inbound 22 and llm_ports only from the configured CIDRs;
  outbound 80/443 (packages, images, model weights) and 53/udp (DNS) only.
  Variable validation rejects 0.0.0.0/0 and ::/0 at plan time.
- Compute: flexible-shape dynamic block (shape_config only for Flex shapes),
  Ubuntu image resolved per shape architecture, public IP on the primary VNIC,
  cloud-init in `metadata.user_data`.
- Storage: 200 GB Balanced volume in the instance's availability domain,
  paravirtualized attachment, mounted by ext4 label `llmswarm` with a `nofail`
  fstab entry and a retrying systemd unit.
- cloud-init prepares `models/`, `cache/` (root-owned, for the Ollama container)
  and `state/` (uid 10001, for the orchestrator) on the data volume. It carries
  no credential.
- Outputs expose the public IP, volume id/attachment/device/size/mount point,
  VCN/subnet/security-list ids, the ingress inventory, the loopback endpoints
  and an SSH command.

6. Portability
--------------
The root variables and outputs are provider neutral (region, vcn_cidr,
subnet_cidr, ssh_allowed_cidrs, llm_api_cidrs, llm_ports, instance_shape and
sizing, block_volume_size_gbs, volume_mount_point). Porting to AWS or GCP
replaces `provider.tf` and the three module bodies:

  network  VCN/IGW/route table/security list/subnet
             -> VPC/IGW/route table/security group/subnet (AWS)
             -> VPC network/firewall rule/subnetwork (GCP)
  compute  oci_core_instance A1.Flex
             -> aws_instance t4g.xlarge
             -> google_compute_instance t2a-standard-4
  storage  oci_core_volume + attachment
             -> aws_ebs_volume gp3 + attachment
             -> google_compute_disk pd-balanced + attached disk

Only OCI is validated; AWS and GCP remain documented ports.

7. Defects found and fixed during verification
----------------------------------------------
- None in the configuration. The first attempt to build a local tfvars used a
  relative path one directory short (`../09-...` instead of `../../09-...`);
  the copy failed, no file was written, and the corrected path produced the
  file used for the plan. This is an operator-command slip, not a module
  defect.

8. Not verified at Stage 2
--------------------------
- No `tofu apply`: nothing exists in OCI. Capacity for `VM.Standard.A1.Flex`
  is only proven by a successful apply, and A1 capacity is often exhausted;
  `availability_domain` is the documented escape hatch.
- cloud-init is not executed until an instance boots. The volume discovery,
  first-boot mkfs, fstab entry, systemd unit and directory ownership are
  therefore unproven on a real host.
- The block volume attachment path `/dev/oracleoci/oraclevdb` is the
  documented paravirtualized device, not an observed one.
- No SSH, Docker install, stack deployment or model download was performed;
  those are Stage 5.
- No cost measurement. The plan's 8 resources are list-price billable except
  for the Always Free A1 allowance and the first 200 GB of block storage.
- The Stage 5 Compose override that bind-mounts `/mnt/llm-swarm` into the
  containers does not exist yet; today the stack uses named Docker volumes.
