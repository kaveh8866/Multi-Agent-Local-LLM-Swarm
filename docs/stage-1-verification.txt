workstation (PID 3764, loopback only), so the local `.env` sets

6. Budget enforcement (same stack, same model)
----------------------------------------------
POST /v1/tasks with constraints.max_steps = 4
  200, wall time 9.811 s
  status      budget_exhausted
  steps       4
  plan        3 subtasks
  errors      ["step budget 4 exhausted before stage 'synthesise'"]

Four model calls were spent on the plan plus three fan-out delegations, and the
run stopped before synthesis instead of silently truncating the answer. This is
the intended contract: the effective budget is the minimum of the task, the
workflow and SWARM_MAX_STEPS.

7. Defects found and fixed during verification
----------------------------------------------
- Root compose entrypoint failed to resolve: "service llm-runtime refers to
  undefined volume model-weights". `extends` inherits volume references, so the
  root file now declares the same top-level volumes and bridge network. `docker
  compose config -q` from the repository root returns 0.
- The task API did not consume the request body when it rejected a request for a
  missing token. On a keep-alive connection the unread body was parsed as the
  next request line ("Bad request version ..."), corrupting the following
  request. The 401 and 404 paths now drain a bounded body (closing the
  connection when the declared length exceeds 256 KiB), and a regression test
  sends an unauthorized request followed by an authorized one on one
  connection: 401 then 200, no parse error in the log.
- Two unit-test expectations were wrong, not the code: `-3 + 7 % 4` is 0 (not
  -2) and "Local models are private. They are also cheap." is 8 words (not 9).
  The assertions were corrected.

9. Not verified at Stage 1
--------------------------
- No OCI infrastructure exists. terraform/ holds the Stage 2 contract and no
  .tf file; nothing has been planned or applied.
- No model-quality claim. The smoke model is qwen2.5:0.5b because it fits a
  laptop; its answers are shallow. Task success, latency and memory for a
  production-sized model belong to Stage 4/5.
- No concurrency or load test. The stack served one task at a time; fan-out is
  sequential inside a single run loop.
- No live tool invocation was observed: the smoke model never emitted a tool
  request, so the calculator/text_stats gateway is covered by unit tests only,
  not by a model-driven call.
- The vLLM GPU override is syntax-validated only; this workstation has no GPU
  and the image was not pulled.
- The API is a loopback control plane with one shared bearer token. There is no
  per-user identity, TLS termination or audit retention.
