1. STARTING POINT
--------------------------------------------------------------------------------
The repository at `projects/10-multi-agent-local-llm-swarm` had its own `.git` and
eight stage commits on `main`, but the run failed four release requirements:

  - no licence file at all;
  - commit author and committer were the generic tool identity `User`, not the
    operator;
  - every message ended in an AI attribution footer (12 matching lines across the
    eight messages) — the project's own AGENT_GUIDE §14 forbids them;
  - the GitHub remote held a single unrelated placeholder commit (`7c320df`,
    "Initial commit") with its own root history, so no push of the local history
    could ever fast-forward.

Requirements for this stage, restated so the record is checkable:
the repository independent, `origin` = the URL above, default branch `main`, MIT
`LICENSE` with "Copyright (c) 2026 Mostafa Kaveh", commits authored as Kaveh with
zero footers, a release commit, `main` pushed, `v1.0.0` published, and the vault
row updated to `PORTABLE_CERTIFIED` 100/100.

7. PUSH AND REMOTE VERIFICATION
--------------------------------------------------------------------------------
Because the remote root (`7c320df`) is unrelated to the local root (`d2f811f`), a
normal push is rejected as a non-fast-forward. The rewrite was pushed with an
explicit lease so the update could not silently overwrite newer remote work:

  $ git push --force-with-lease origin main
   + 7c320df...b52964c main -> main (forced update)
  $ git push origin v1.0.0
   * [new tag] v1.0.0 -> v1.0.0

  $ gh repo view kaveh8866/Multi-Agent-Local-LLM-Swarm \
      --json visibility,defaultBranchRef,isPrivate
  { "default": "main", "private": false, "visibility": "PUBLIC" }

  $ git rev-parse HEAD origin/main
  b52964c44fb7a055fa1fd8ec090615263be4190e
  b52964c44fb7a055fa1fd8ec090615263be4190e

  $ git status --short
  (no output)

Local and remote are the same commit, the working tree is clean, the default branch
is `main` and the repository is public.

**Licence detection.** GitHub's detector reads the pushed file, not just its name:

  $ gh api repos/kaveh8866/Multi-Agent-Local-LLM-Swarm/license \
      -q '{spdx:.license.spdx_id,name:.license.name,path:.path}'
  {"name":"MIT License","path":"LICENSE","spdx":"MIT"}

So the remote's licence badge and the repository's licence field resolve to MIT
from the same blob the tree equality in §4 covers. (One intermediate check of the
`licenseInfo` field on `gh repo view` came back empty; the dedicated licence
endpoint above is the authoritative answer and is what this record relies on.)

**No GitHub Release object.** `v1.0.0` is a pushed annotated tag; no Release entry
was created, so the tag page has no release notes body. The tag is the released
artefact this record certifies.
